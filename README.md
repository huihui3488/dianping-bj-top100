# 北京餐厅 Top100

课程项目「大众点评北京餐厅 Top100」的成果站点：采集、解析、建模的结果与源码。静态页面，零外部依赖，断网也能完整打开。

## 四个页面

| 页面 | 内容 |
|---|---|
| `index.html` | 概览：首屏前三名、榜单的三条结论、四段流水线、其他页入口 |
| `results.html` | 榜单：100 行明细（可搜索、筛选、排序）、六张图、可调口径的实验台、对照实验表 |
| `code.html` | 代码：三个脚本的完整源码（带行号与着色）、字段契约、实现取舍、16 条问答 |
| `method.html` | 口径：公式、三道闸门、权重论证、相关性检验、七条局限 |

采集日期 2026-10-15，候选 150 家，入榜 100 家，分属 100 个品牌。

## 口径

```
综合分 = 0.625 × minmax(评分) + 0.375 × minmax(ln(1 + 评论数))
```

三道闸门：评论数门槛 2000（150→148），双维度加权排序（同分依次比评分、评论数、店名），品牌限额每家 1 席（→100）。

权重来源：原设计为「评分 0.50 / 评论数 0.30 / 客流量 0.20」。客流量维度因数据源不存在被删除，剩余两维按原 5:3 比例等比放大到合计 1.0。

## 如何更新

`assets/data.js` 与 `assets/code.js` 由仓库外的 `build_site.py` 生成。建模产物如有更新，替换 `top100.csv` / `cuisine_full.csv` 后重跑：

```bash
python build_site.py
```

构建脚本同时做一次端到端校验：用与 `build_ranking.py` 等价的实现重算整条流水线，断言名次与 `top100.csv` 完全一致（当前 100/100）。校验不过会打印差异，不会静默生成错数据。

`code.js` 生成时会顺带把三位成员源码里少数面向课堂演示的注释改成中性表述，逻辑不动，改写条数在构建日志里。

## 如何发布

```bash
python deploy.py            # 资源版本号 +1，并把页面推到 GitHub
python deploy.py --no-bump  # 只推送，不改版本号
```

页面里的 `assets/*.css|js` 都带 `?v=N`。GitHub Pages 对静态资源有约 10 分钟强缓存，改完不换版本号，别人可能刷出旧版 JS。`deploy.py` 会自动递增 N。

## 兼容性

- 无 CDN、无 Web Font、无前端框架，`fetch` 也未使用（数据以 `assets/data.js` 全局注入），双击 `index.html` 用 `file://` 打开同样正常。
- 打印样式已处理（`@media print` 隐藏导航与实验台、取消代码块高度限制），可直接导出 PDF。
- 图表全部是手写 SVG，没有图表库；数字统一用 Georgia，表格里等宽对齐。
